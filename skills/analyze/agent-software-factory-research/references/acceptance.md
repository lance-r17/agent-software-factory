# 验收、预览与 PR 清单

## 1. Skill 与构建验证

- 每个 Skill 都有 `SKILL.md`，frontmatter 仅使用开放规范字段。
- `name` 符合小写连字符规则并匹配父目录；description 非空且不超过 1024 字符。
- metadata 的键和值都是字符串；SKILL.md 建议少于 500 行。
- `scripts/` 和 `references/` 的相对链接真实存在。
- 网页注册表覆盖所有部署 Skill，无重复导入、遗漏文件或内联 `content` 模板字符串。
- 执行 `npm run build`，不能通过弱化构建脚本绕过错误。

## 2. 生产浏览器矩阵

在生产 `dist/` 上验收，不用开发服务器代替。至少覆盖：

- 中文和英文首页及所有既有方案路由。
- 中文和英文桌面视口。
- 中文和英文 375px 移动视口。
- 当前方案语言切换和页内锚点保留。
- 桌面 Tabs、移动 dropdown 选择、Escape、焦点恢复。
- SKILL 手册全文模态框、真实剪贴板复制和真实下载。
- 无控制台错误、无本地 404、无移动横向溢出、无失效链接。

正文抽离类重构还应比较迁移前后的页面正文、Skill 卡片和手册模态框 SHA-256；全部一致才能证明展示与内容未变。

## 3. 网站版本与恢复快照

- 构建和浏览器验收通过后保存静态网站版本。
- 快照必须包含 `src/`、配置文件和完整 `skills/`，不能只包含网页注册表。
- 运行宿主快照脚本并核验相对路径集合与逐文件 SHA-256。
- 确认快照中的每份 SKILL.md 与仓库源文件一致；缺失时必须停止，不能声称可恢复。
- 保存版本不等于公开发布。公开 Pages 只在人工 merge 且 Actions 成功后更新。

## 4. 推送与 PR

- 当前分支正确、工作区干净、main 是 HEAD 祖先。
- 同名远端分支已检查；分叉时停止，不强推。
- 变更不含 `dist/`、`node_modules/`、`.git/`、`state/`、`.github/workflows/` 或密钥。
- 真实 `git push` 优先；授权和 TLS/SSH 回退严格按宿主手册执行并清理凭据。
- 远端分支 tip、PR headRefOid 和本地 HEAD 一致。
- PR 包含方案或重构范围、核验日期、来源、构建和浏览器验收、网站版本、快照、安全边界及关联 Issue。
- 只创建或更新 PR，不自动 merge、不关闭 Issue、不删除分支。

## 5. 记录

每日方案使用宿主 `record_run.py` 写入跨运行状态，不能手工编辑 state。功能重构不占每日方案份额。记录后再次执行防重检查，应返回当天已有成功记录。
